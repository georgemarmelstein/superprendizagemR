# Projeto Final: Prompt Engineering Portfolio

## Objetivo

Criar um portfolio completo demonstrando domínio de engenharia de prompts aplicado a um domínio específico.

---

## Requisitos do Projeto

### 1. Escolha do Domínio (obrigatório)

Selecione UMA área:
- Marketing e Conteúdo
- Desenvolvimento de Software
- Análise de Dados
- Educação
- Negócios e Estratégia
- Pesquisa
- Outro (especificar)

### 2. Componentes Obrigatórios

Seu portfolio deve incluir:

#### A. Biblioteca de Prompts (mínimo 10)
- Pelo menos 3 técnicas diferentes (CoT, Few-Shot, Chaining, etc.)
- Documentação clara de cada prompt
- Casos de uso específicos

#### B. Prompt Chain Complexo
- Mínimo 5 etapas
- Resolva problema real do domínio
- Documentação do fluxo

#### C. Comparações e Otimizações
- Mostre evolução de pelo menos 3 prompts
- Versão inicial → versão otimizada
- Justifique mudanças

#### D. Casos de Teste
- Para cada prompt principal:
  - 2-3 exemplos de input
  - Outputs esperados
  - Critérios de avaliação

#### E. Guia de Melhores Práticas
- Baseado em suas descobertas
- Específico para seu domínio
- Armadilhas comuns e soluções

### 3. Estrutura Sugerida

```
seu-portfolio/
├── README.md (visão geral)
├── biblioteca-prompts/
│   ├── categoria-1/
│   ├── categoria-2/
│   └── ...
├── chains/
│   ├── chain-complexa-1.md
│   └── chain-complexa-2.md
├── evolucao/
│   ├── prompt-1-evolucao.md
│   └── ...
├── testes/
│   └── casos-de-teste.md
└── guia-praticas.md
```

### 4. Critérios de Avaliação

- **Diversidade técnica** (20%): Uso de múltiplas técnicas
- **Aplicabilidade prática** (25%): Quão úteis são no mundo real
- **Documentação** (20%): Clareza e completude
- **Otimização** (20%): Demonstração de refinamento
- **Criatividade** (15%): Soluções inovadoras

## Entrega

### Formato
- Repositório Git ou pasta organizada
